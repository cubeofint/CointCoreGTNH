# Cluster follow-up: Alpha, Endgame, Hub

## Установка и настройки

Обновить CointCore на всех трёх узлах и клиентах одной сборкой. Формат состояния карточной игры изменён; старый клиент оставлять нельзя.

`tools/configure-cluster-followup.py` сначала запускается без аргументов на Linux для просмотра настроек. Он использует каталоги `/opt/minecraft/gtnh/gtnh`, `/opt/minecraft/gtnh/endgame`, `/opt/minecraft/gtnh-test/hub`; пути можно заменить аргументами `--alpha`, `--endgame`, `--hub`. `--apply` требует остановленных трёх JVM, создаёт резервные копии конфигов и сохраняет владельцев файлов. Миры, whitelist, пароли БД и адреса прокси не меняются.

Настройки в секции `cluster`:

```text
S:accessAuthorityNodeId=alpha
B:accessSyncOperators=true
S:newPlayerNodeId=alpha
S:hubNodeId=hub
B:hubSendsHome=false
B:migrationEnabled=true
S:migrationQuestSourceNode=alpha
S:migrationQuestTargetNode=endgame
```

`assignHomeOnFirstJoin=true` только на Alpha. Общая `migrationSharedDirectory` должна быть доступна для чтения и записи всем узлам. Включение синхронизации OP означает, что список операторов Alpha становится главным, в том числе для удаления устаревших операторов на других узлах. Запускать сначала Alpha.

В `S:migrationQuestId=` вручную указать UUID отдельного квеста с галочкой. Пустое значение отключает триггер. Получение самой LuV-эпохи не запускает перенос. Скрипт это поле не заполняет.

## Согласованный перенос команды

На исходном узле: `/migrate request <ник> endgame`, либо основная кнопка `/migrate ui`. Все участники, которые онлайн во время согласования, должны ответить в чате. Выход из игры не заменяет согласие; любой отказ отменяет запрос. После согласия есть предупреждение и 15 секунд перед отключением. Офлайн-участники также включены в перенос. Запрос действует 10 минут и отменяется после перезапуска исходной JVM.

Старый ZIP → очередь → импорт в окне сохранён для ручного восстановления. Он не равен полному переносу с отключением источника; для обычной миграции использовать верхнюю кнопку или `request`/`move`.

## Игрок Alpha вступает в существующую команду Endgame

После обычного вступления SU на целевом узле создаётся запрос на исходный домашний узел. Игрок подтверждает перенос личных данных. Переносятся его профиль, инвентарь, прогресс, дома и индивидуальные данные, поддержанные экспортом; домашний сервер меняется после завершения.

Персоналка, блоки и приваты прежней команды не включаются в этот архив. Игрок удаляется из старой команды SU и группы квестов только на этапе отключения источника. Если он был владельцем, владельцем становится оставшийся участник. Если участников больше нет, база и команда не удаляются: оставшуюся команду без владельца администратор разбирает отдельно.

На цели сохраняются существующая команда и её владелец. Если приглашение/членство отозвано либо владелец сменился, автоматический импорт останавливается. При отказе от согласования данные остаются на исходном сервере; вступление SU на цели само по себе ещё не означает завершённый перенос.

## Существующие базы LuV+

На Alpha:

```text
/migrate batch plan luv endgame
/migrate batch run <ID-плана>
/migrate batch status <ID-плана>
/migrate batch stop <ID-плана>
```

`plan` только записывает список команд с персоналкой и хотя бы одним участником LuV или выше по приоритетам эпох. После просмотра списка `run` переносит по одной команде обычным механизмом журналируемой миграции. Команды должны быть офлайн; онлайн-команды переносить через согласование. Изменение состава/персоналок, конфликт или ошибка останавливают очередь. `stop` останавливает очередь, но не прерывает уже начатый перенос. После перезапуска очередь сама не возобновляется. Состояние `dispatching` после аварии требует проверки журнала, автоматического повтора нет.

## Права и гости

Гостевые `/fly`, `/god`, `/nv` без аргументов переключают временные возможности на чужом узле. Они не дают права менять другого игрока и не превращаются в постоянную привилегию на домашнем узле. Согласование миграции и карточные игры доступны гостям.

Удалённые `/fly <ник>`, `/god <ник>`, `/heal <ник>` требуют прав исходного отправителя. В предоставленном конфиге у `[admin]` были права на действие над другим игроком, но отсутствовали некоторые права на запуск самой команды. Если этому рангу они нужны, добавить в него:

```text
command.serverutilities.fly: true
command.serverutilities.god: true
cointcore.command.heal: true
command.cointcore.heal: true
cointcore.fly.other: true
cointcore.god.other: true
serverutilities.other_player.heal: true
```

Явные запреты moderator не заменяются. Синхронизация переносит определения прав и глобальные назначения рангов с Alpha; текущие эпохи сохраняются на домашней ноде и переносятся миграцией. Это не непрерывная синхронизация инвентарей между всеми гостевыми копиями игрока.

В Tab сохраняются префиксы удалённых игроков и название узла. На Hub отключены меню путешествий и штатная/заменённая очистка предметов. Существующий мир хаба и его постройки не удаляются; регистрацию измерений другими модами это не отменяет.

## Проверка перед выдачей игрокам

Локально: сборка с Checkstyle; отдельная Forge JVM; проверки гостевого разрешения через настоящий интерфейс SU, переключения и снятия возможностей; проверка исполнения трёх команд от удалённого отправителя; сохранения старой команды при переносе игрока, приглашения и смены владельца; согласований, бонусов чанков и домов; УНО.

На двух тестовых узлах ещё проверить:

1. Согласие/отказ участников на разных узлах, затем полный перенос с галочкой нужного квеста.
2. Вступление одного игрока в команду Endgame: инвентарь, дома, квесты, киты; старая персоналка и остальные участники остаются на Alpha.
3. Очередь LuV+: одна свободная команда и одна с конфликтом; после конфликта следующие команды не должны стартовать.
4. Роль и OP с Alpha после входа на Endgame/Hub, Tab и удалённые команды с правами и без них.
5. Новый аккаунт через Hub попадает на Alpha; существующий аккаунт не получает автоматический возврат с Hub.
6. УНО с тремя участниками и наблюдателем: проигравший выбывает, зритель не играет и не видит чужую руку.

Откат `/expadd` отложен по запросу владельца до выбора параметров. Изменение цветов/префиксов через личный кабинет также отложено отдельно.
