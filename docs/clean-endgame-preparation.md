# Чистая нода Endgame со спавнами ALPHA

`tools/prepare-endgame.cjs` запускается через Node.js 18+ без npm-пакетов. Скрипт создаёт **отдельный пакет мира и меню**, не полный сервер. Исходный ALPHA остаётся неизменным. Требуется остановленный сервер либо согласованный офлайн-снимок: `save-all` работающего сервера не заменяет остановку. На Linux скрипт дополнительно проверяет рабочие каталоги Java-процессов через `/proc`.

## Состав пакета

- Сид, генератор, правила мира и координаты основного спавна из `level.dat`; таблица Forge/FML ID сохраняется и проверяется побайтно после записи.
- Каждая включённая точка `config/cointcore/world_travel.json`, плюс основной спавн из `level.dat`: выбирается связный по сторонам участок приватов того же владельца. **Это геометрический критерий, а не распознавание построек.** Если к спавну примыкает другая территория той же команды, она также попадёт в план; перед подготовкой необходимо проверить границы.
- Только выбранные чанки из Anvil-файлов. Сохраняются блоки, TileEntities, сущности и отложенные обновления; сжатые записи чанков проверяются по SHA-256. Целые исходные region-файлы не копируются.
- Команды SU, их настройки защиты и минимальные профили владельцев/участников для сохранения принадлежности. Копируются только выбранные приваты, флаги прогрузки и восстановления старой прогрузки снимаются. Инвентари и дома этих администраторов не копируются.

Не копируются `playerdata`, статистика, содержимое `World/data`, персоналки, станции и корабли, глобальные ресурсы модов, Forge tickets, менеджеры `chunkapicore`, старое распределение динамических ID измерений. Из `Forge` в `level.dat` сохраняется только `DefaultFluidList`; FML сохраняется полностью. Сохранённые в самих чанках предметы и сущности спавнов копируются намеренно. Работа спавновых механизмов, зависящих от глобального состояния модов, требует проверки в игре.

Папки измерений: Overworld — `World/region`, остальные точки — `World/DIM<ID>/region`. Нет нужной папки или чанка, конфликтует приват, отсутствует профиль владельца — подготовка завершается ошибкой. Неполный результат помечается `INCOMPLETE`; устанавливать его нельзя. Скрипт не дополняет и не перезаписывает существующие выходные каталоги.

## Команды на Linux

Загрузить `prepare-endgame.cjs` в `/opt/minecraft/gtnh/prepare-endgame.cjs`. Остановить ALPHA через MCSManager, сделать резервную копию. План создаётся из актуальных файлов непосредственно на Linux, а не из присланных для диагностики архивов:

```bash
node /opt/minecraft/gtnh/prepare-endgame.cjs plan \
  /opt/minecraft/gtnh/gtnh World \
  /opt/minecraft/gtnh/endgame-spawn-plan.json
```

Проверить `areas`: измерения, владельцев, количество и границы чанков. Для проверенного снимка ALPHA от 13 ноября 2026 получалось 35 областей и 1559 чанков; это не зашитый в код лимит. Сохраняемый сид: `-5933295`, генератор `RWG`. При изменении входных файлов после составления плана подготовка откажет.

```bash
node /opt/minecraft/gtnh/prepare-endgame.cjs prepare \
  /opt/minecraft/gtnh/gtnh World \
  /opt/minecraft/gtnh/endgame-world-bundle \
  /opt/minecraft/gtnh/endgame-spawn-plan.json --offline-snapshot
```

На выходе: `World/`, `config/cointcore/world_travel.json`, `report.json`. Отсутствие `INCOMPLETE` и успешное завершение команды обязательны. `report.json` содержит хеши записей всех перенесённых чанков, входных файлов и список исключённых категорий данных. Существующий пакет при повторном запуске не заменяется: выбрать новое имя каталога.

## Установка и проверки

1. Создать новый, остановленный экземпляр **той же серверной сборки**, с теми же модами, скриптами, конфигами генерации и статическими ID измерений. Это не копирование всех каталогов рабочего сервера: его `cointcore` содержит также локальные журналы, купленную прогрузку и прочее состояние. Динамические персоналки, станции и корабли не регистрировать через скопированные конфиги.
2. У нового экземпляра не должно быть существующего `World`. Установить `World` из пакета, затем файл меню, сохранив владельца файлов, под которым MCSManager запускает сервер. Старый мир при необходимости сначала архивировать отдельно, не сливать каталоги.
3. Настроить отдельный порт, `nodeId=endgame`, `assignHomeOnFirstJoin=false`. Подключить к рабочему кластеру только после проверки на изолированных тестовых нодах. Использовать одинаковые UUID/режим авторизации и согласованные настройки БД/миграций; не переносить тестовую БД в рабочий кластер.
4. После запуска проверить основной спавн и все 34 точки меню: площадки, блоки, содержимое, защиту SU обычным игроком, требования квестов. Одинаковый сид не обещает совпадения новой генерации со старой версией сборки: проверять границы скопированных участков.
5. Проверить перенос небольшой команды с внешним приватом и прогрузкой, затем перезапуск обеих нод. Станции/корабли являются отдельным сценарием и подготовкой чистой ноды не переносятся.

Оставшиеся задачи эксплуатации: первоначальное назначение домашних нод офлайн-игрокам ALPHA и политика LuV. Этот скрипт не меняет маршрутизацию и не вводит автоматическое выселение по эпохе.

Проверки разработки: `node --test tools/prepare-endgame.test.cjs`. Синтетические тесты проверяют разреженные region-файлы, отрицательные координаты, повреждённые записи, NBT/ID, отсутствие чужих чанков/домов/прогрузки, отказ при изменённом плане и существующем выходе. Присланные реальные NBT/приваты использованы для проверки плана; реальные region-файлы и запуск полного результата на сервере разработчику не предоставлялись.
